Trust · Security overview

Security is a
release gate.

Tiny handles children’s educational records and guardian contact data. The design is privacy-first and closed by default, but this page is an engineering overview, not a certification or a claim that production security review is complete.

Current preview controls

  • Encrypted local Room database using SQLCipher; the passphrase is wrapped by an Android Keystore key.
  • No real pupil or guardian data; deterministic synthetic demo records only.
  • Mock SMS adapter with no provider calls and no spend.
  • No production Firebase project, no live cloud data, no deployed functions.
  • No parent app, parent login or pupil account.
  • All content on this page is static and collects no personal data.

Designed controls for the connected product

  • Firebase Auth and App Check on callable commands; Firestore rules deny direct client writes to authoritative records.
  • Workspace and class scope derived from server-side membership, never from client-supplied IDs.
  • Idempotent sync commands, optimistic versions, immutable attendance submissions and append-only corrections.
  • Timing-safe HMAC verification and replay/event dedupe for provider webhooks.
  • No pupil PII in AI prompts; output validation and teacher review before parent sharing.
  • Secrets in Secret Manager/CI secrets, never in Git, the APK or logs.

What is not yet complete

A non-production Firebase project and access, App Distribution tester access, a supported on-device Gemini Nano device, native-language review, DPIA/legal review, provider KYC, production SMS budget and a full penetration/security release review remain external gates.

Report a concern

Use the public issue tracker for non-sensitive concerns. Do not include real pupil data, phone numbers, secrets or exploit details in a public issue.
